# Decision Log & Open Issues v1.0

## 1. 현재 결정사항
| 항목 | 결정 |
|---|---|
| AI 모델 | 자체 LLM 개발하지 않고 승인된 LLM API 사용 |
| LLM 호출 위치 | Backend/AI Orchestrator에서 서버 측 호출 |
| 초기 배포 | Linux + Docker |
| 향후 확장 | K8s 전환 가능 구조 유지 |
| Version | 결과물 상태 관리 |
| History | 작업/의사결정 과정 관리 |
| 파일 저장 | DB와 분리된 File Storage |
| 긴 AI 작업 | Async Job 확장 구조 |
| 디자인 시스템 | 기존 NH 자산과 연결, 중복 구축 최소화 |
| 브랜드 시안 제작 (FR-13) | 카드 실물·홍보물의 **컨셉 시안**까지만 다룬다. 인쇄용 최종 파일(규격·CMYK·재단선)은 범위 밖 |
| 브랜드 시안 파이프라인 | 새 테이블·엔드포인트를 만들지 않고 FR-05의 AI Job을 `job_type = BRAND_CONCEPT`으로 재사용 |
| 시안 3안과 Version | 3안은 후보이며 Version이 아니다. 사용자가 하나를 **선택할 때** Version 1개가 생성된다 |
| 책임성 검토 (FR-14) | AI는 **준법 검토가 필요한 지점을 제시**할 뿐 적법성을 판정하지 않는다. Export·공유를 차단하는 게이트가 아니다 — PRD 5절 비범위를 넘지 않는다 |
| 책임성 검토의 근거 | 목업에서 그대로 인용한 근거가 없는 지적은 **서버에서 버린다.** 담당자가 검증할 수 없는 지적은 결정을 내릴 수 없기 때문 |
| 책임성 규칙 정본 | [docs/guidelines/RESPONSIBLE_DESIGN.md](docs/guidelines/RESPONSIBLE_DESIGN.md). 코드의 규칙 배열은 프롬프트를 규칙에서 생성하기 위한 사본이며, 정본이 아니다 |

## 2. 반드시 협의해야 할 사항
### 인프라
- Linux 서버 사양
- Docker 운영 방식
- 내부 DNS/Reverse Proxy
- 컨테이너 이미지 반입 경로 및 Registry
- 운영/개발 서버 분리
- NFS/Object Storage 종류와 접근권한
- DB/Redis 운영 주체

### AI
- LLM API endpoint
- 인증 방식(Token/API Key/OAuth 등)
- 사용 가능한 모델 목록
- 최대 입력/출력 토큰
- 동시 호출 제한
- Timeout/Rate Limit 정책
- Prompt/Response 저장 허용 범위
- 시안 3안 동시 생성이 LLM 호출 3회인지 1회인지 (FR-13) — 동시 호출 제한·최대 토큰 정책과 직결

### 보안
- SSO 방식
- 프로젝트 권한 모델
- 파일 반출 정책
- 로그/감사로그 보존 정책
- AI 입력 데이터의 민감정보 처리 기준
- HTML preview 보안 정책

### 업무
- 공식 NH Template의 관리 주체
- 개인 Template 공유 허용 범위
- Version 승인 개념 필요 여부
- 준법/보안 검토를 워크플로우에 넣을지 여부 — FR-14가 `준법 검토 요청` **결정 상태**까지는 만들었다. 아래 3건이 정해져야 실제로 넘어간다
- **준법 검토 요청의 수신자** (FR-14) — 누구에게 가는가. 현재는 상태로만 남고 아무에게도 전달되지 않는다
- **준법 검토 요청의 알림·SLA** (FR-14) — 어떻게 통지하고 며칠 안에 회신하는가
- **책임성 규칙의 개정 주체** (FR-14) — RR 규칙 추가·삭제를 누가 승인하는가
- 최종 Export 형식 우선순위
- **NH 실제 브랜드 자산(로고·캐릭터·컬러·서체) 파일의 반입 경로와 관리 주체** — FR-13 최대 블로커. 자산이 없으면 기능이 동작해도 결과가 NH답지 않다
- 카드 실물의 필수 표기 요소(카드사 로고, 은행명, 법정 문구) 규칙의 출처와 관리 주체
- 브랜드 시안 컨셉의 Export 형식 (PNG / PDF / HTML) — 위 Export 형식 우선순위와 함께 협의

## 3. 중요한 제품 의사결정
### Q1. 이 서비스는 디자인 시스템인가?
**아니다.** 디자인 시스템은 구성요소 중 하나이며, 제품의 중심은 업무 제작과 협의/의사결정 관리다.

### Q2. AI가 최종 판단하는가?
**아니다.** AI는 의견과 수정안을 제안하고, 최종 반영 여부는 담당자가 결정한다.

### Q3. 댓글/Version만 있으면 차별점이 되는가?
**아니다.** 핵심은 의견을 의사결정과 Version에 연결하고 이후 업무에서 재사용 가능한 자산으로 남기는 것이다.

### Q4. 카드·홍보물 시안을 만드는 것은 Q1(디자인 시스템이 아니다)의 번복인가?
**아니다.** FR-13은 새 디자인 체계를 세우지 않는다. 기존 NH 자산을 배치해 **방향 합의용 컨셉 시안**을 만들 뿐이고, 값은 시안 자체가 아니라 "어느 방향으로 갈지"가 Version·History에 기록되는 데 있다. 제품의 중심이 업무 제작과 의사결정 관리라는 Q1의 결론은 그대로다.

## 4. 향후 확장 방향
현재 프로젝트에서 축적되는 프로젝트/Template/Review/History 데이터는 이후 RAG와 유사업무 추천, 업무사례 검색, Agent 자동화의 입력 자산이 될 수 있다.
