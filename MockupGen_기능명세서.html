2 개요

2.1 목적

기획자가 작성한 기획안 텍스트를 입력하면 AI가 실행 가능한 HTML 목업 화면을 생성하고, 팀원이 버전별로 의견 · 채팅으로 피드백하며, 최종적으로 한국어 화면 기획서(HTML)까지 자동 생성하는 기획–디자인 협업 워크플로우 도구.

2.2 범위

본 명세서는 project.html 한 화면이 제공하는 전 기능을 다룬다. 프로젝트 생성 · 삭제 · API 키 설정은 index.html 소관이므로 참조 수준으로만 기술한다.

2.3 용어 정의

용어정의
프로젝트하나의 화면 개선 과제 단위. 목업 · 참조화면 · 담당자 · 채팅을 소유
목업(Mockup)AI가 생성한 자체 완결형 HTML 문서 1건. 버전 번호를 가짐
버전동일 프로젝트 내 목업의 순번 (v1, v2, …). 생성 시 자동 증가
참조 화면AI에게 디자인 스타일을 학습시키기 위해 업로드하는 기존 화면 이미지
의견(Comment)목업 버전 단위로 달리는 피드백
채팅(Chat)프로젝트 단위로 이어지는 대화
현재 사용자헤더에서 선택한 활동 주체. 로그인이 아닌 계정 전환 방식
기획서(Spec)목업 캡처 이미지 + 기획안을 근거로 AI가 작성한 7섹션 한국어 문서

3 시스템 구성

3.1 기술 스택

계층사용 기술
마크업 / 스타일HTML5, Tailwind CSS (CDN), 인라인 style
스크립트Vanilla JavaScript (ES2020+, 빌드 도구 없음)
데이터 저장브라우저 localStorage (서버 · DB 없음)
AI 연동Anthropic Messages API 직접 호출 (api.anthropic.com/v1/messages)
화면 캡처html2canvas 1.4.1 (cdnjs, 최초 사용 시 동적 로드)
앱화PWA — manifest.json, sw.js Service Worker 등록

3.2 아키텍처 특징

  • 백엔드 없음. 모든 로직 · 데이터가 브라우저 안에서 완결된다.
  • 단일 파일 배포. 번들러 · 프레임워크 없이 정적 호스팅(GitHub Pages)만으로 동작.
  • AI 직접 호출. 프록시 서버 없이 브라우저가 Anthropic API를 호출한다 (anthropic-dangerous-direct-browser-access: true 헤더 사용).

3.3 외부 의존성

대상용도실패 시 영향
cdn.tailwindcss.com전체 스타일레이아웃 전면 붕괴
api.anthropic.com목업 · 기획서 생성생성 기능 불가 (조회는 정상)

Mockup

필드타입설명
idstringUUID

Comment / ChatMessage

두 엔티티 모두 id, userId, content, createdAt 구조를 갖는다. Comment는 목업 버전에, ChatMessage는 프로젝트에 종속된다.

4.3 데이터 생명주기

  • 목업 삭제 → 해당 mg_comments_{mockupId} 동시 삭제 (연쇄 정리 수행)
  • 프로젝트 삭제(index.html) → 소속 목업의 댓글 + refs/mockups/members/chat 키 일괄 삭제
  • 사용자 삭제 기능은 없음

│           │  │ v2 | 메모 | 뷰모드 · 기획서 │ │  ┌ 의견|채팅 ┐ │
│  참조     │  │      · HTML · 의견/채팅     │ │  │           │ │
│  생성     │  └────────────────────────────┘ │  │  타임라인  │ │
│  히스토리 │      <iframe srcdoc>            │  │           │ │
│  담당자   │                                 │  ├ 입력 폼 ──┤ │
└───────────┴────────────────────────────────┴─────────────────┘

5.2 모바일 레이아웃 (<768px)

  • 좌/우 패널이 하단 바텀시트로 전환 (translateY(100%) → 0)
  • 하단 고정 5탭 네비게이션: 생성 / 히스토리 / 의견 / 채팅 / 담당자
  • 반투명 오버레이 탭 또는 아래로 스와이프(60px 이상) 시 닫힘
  • 뷰 모드 전환 버튼 · 우패널 토글 버튼 숨김
  • env(safe-area-inset-bottom) 으로 iOS 홈 인디케이터 대응

8 비기능 요구사항

8.1 성능

  • 정적 파일 단일 요청 + CDN 2건. 초기 로드 경량.
  • 목업 생성 응답 시간은 AI API에 종속 (통상 수십 초). 진행 상태 UI로 대기 인지 완화.
  • 이미지·HTML 전량을 localStorage에 보관 → 데이터 증가 시 파싱 비용 선형 증가.

8.2 보안

  • 사용자 입력은 전 구간 이스케이프 함수(& < > ") 적용 — XSS 기본 방어.
  • 요소 ID는 crypto.randomUUID() 기반이라 인라인 핸들러 문자열 주입 위험 낮음.
  • 위험 요소는 9.2 · 9.3절 참조.

8.3 호환성

  • 모던 브라우저 기준 (crypto.randomUUID, optional chaining, nullish coalescing 사용).
  • randomUUID 미지원 환경 폴백 존재.
  • 반응형 분기점: 768px.

8.4 PWA

  • manifest.json 연결, 테마 컬러 #4f46e5
  • iOS 홈 화면 앱 메타태그, 192px 아이콘
  • Service Worker 등록으로 오프라인 셸 캐싱

9 제약사항 및 알려진 이슈

9.1 초기 진입 시 최신 목업이 표시되지 않음 기능 결함 P0

현상 (실제 브라우저 확인 완료)

저장된 목업이 있어도 첫 진입 시 중앙 영역이 빈 화면("목업 미리보기")으로 표시되고, 툴바(기획서 · HTML · 뷰 모드)도 노출되지 않는다. 히스토리에서 한 번 클릭해야 정상 표시된다.

부작용 2건

  1. selectedMockup은 최신 버전으로 설정된 상태라 우측 의견 패널에는 해당 버전 댓글이 이미 렌더링된다 → "목업 없음"과 "댓글 있음"이 동시에 나타나는 모순 상태.
  2. 히스토리 탭이 활성인데도 생성 폼과 히스토리 목록이 좌측에 동시 표시된다.

원인

스크립트 최하단 초기화 블록이 상단에서 수행한 자동 선택 결과를 무조건 덮어쓴다.

// 상단 — 최신 목업 자동 선택
if (_initMockups.length > 0) { selectMockup(_initMockups[0]); switchLeftTab('history'); }

// 하단(1046행 부근) — 위 결과를 무효화
showView('empty');
document.getElementById('panel-generate').classList.remove('hidden');

해결 방안

하단 초기화 2줄을 자동 선택 블록 앞으로 이동하거나, if (!selectedMockup) 가드를 추가한다.

9.2 iframe 샌드박스 무력화 보안 P0

목업 뷰어가 sandbox="allow-scripts allow-same-origin" 조합을 사용한다. 이 두 값을 동시에 지정하면 샌드박스가 사실상 해제되어, iframe 내부 스크립트가 부모 페이지의 localStorage에 접근할 수 있다 — 즉 mg_api_key(평문 API 키) 탈취가 가능하다.

  • 시스템 프롬프트에서 "JavaScript 금지"를 지시하지만 AI 출력은 보장되지 않으며, 조작된 localStorage 데이터가 유입되는 경로도 존재한다.
  • 해결: allow-same-origin 제거. (기획서 모달의 iframe은 allow-scripts만 사용해 안전)

9.3 API 키 평문 저장 및 브라우저 직접 전송 보안 P1

mg_api_key가 localStorage에 암호화 없이 저장되고, 브라우저에서 Anthropic으로 직접 전송된다. 공용 PC 사용, 확장 프로그램, XSS 어느 경로로든 키가 그대로 노출된다. 운영 전환 시 서버 프록시 경유 방식으로 변경 필요.

9.4 협업 데이터가 실제로 공유되지 않음 기능 P1

담당자 · 의견 · 채팅 등 협업 UI를 갖췄으나 저장소가 브라우저 로컬이므로 다른 사람 · 다른 기기에서는 전혀 보이지 않는다. 현재 구조는 단일 사용자 데모에 한정된다.

9.5 피드백 루프 단절 기능 P2

의견에 "버튼을 44px로 키워주세요"라고 작성해도 그 내용이 AI 재생성에 전달되지 않는다. 다음 버전을 만들려면 기획안을 처음부터 다시 작성해야 하며, 이전 버전 기반 수정 · 버전 간 비교(diff) 기능이 없다.

9.6 저장 용량 한계 기술 P3

참조 이미지 base64 + 목업 HTML 전량이 localStorage(통상 5–10MB)에 적재된다. 이미지 수 장이면 한도에 도달하며, 현재 Quota 예외 처리는 참조 화면 업로드 경로에만 존재한다. 목업 저장 경로에는 방어 코드가 없다.

9.7 기획서 캡처 정합성 기술 P3

캡처 로직은 iframe 자체가 아니라 HTML을 오프스크린 div에 재렌더한 뒤 촬영한다. head 내 일부 스타일, 외부 리소스, position: fixed 요소 등은 실제 미리보기와 다르게 잡힐 수 있다.
